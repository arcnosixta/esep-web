НАЧАЛО ПРОМПТА
================================================================
Ты — продуктовый аналитик и архитектор. На основе загруженных
источников (TZ/Roadmap.txt, TZ/Roadmap.md, TZ/Tools.txt — проект
ESEP, онлайн-сервис оценки недвижимости в Казахстане) построй
ПОЛНЫЙ ПОШАГОВЫЙ РОАДМАП ПОЛЬЗОВАТЕЛЯ.

ГЛАВНОЕ ТРЕБОВАНИЕ: каждый шаг должен быть соединён стрелкой со
следующим — «после этого идёт это». Никаких разрозненных списков:
только линейная последовательность шагов с видимыми переходами
(шаг 1 → шаг 2 → шаг 3 → ...). Ничего не выдумывай — только факты
из источников. Язык — русский.

================================================================
ЗАДАЧА 1. ПОЛНЫЙ РОАДМАП КЛИЕНТА (главный результат)
================================================================
Построй линейную последовательность из 13 шагов в Mermaid
flowchart LR. Каждый шаг — узел с номером и кратким названием,
стрелкой переходит к следующему. Детали — внутри узла.

  Шаг 1  Регистрация
         Клиент создаёт аккаунт: email/телефон + пароль,
         вход по коду (Supabase Auth).
         ПОСЛЕ ЭТОГО → Шаг 2.
  Шаг 2  Онбординг
         Интерактивная экскурсия по приложению (5 шагов):
         как заказать оценку, что нужно, сколько стоит.
         ПОСЛЕ ЭТОГО → Шаг 3.
  Шаг 3  Профиль и идентификация
         Клиент указывает ФИО и ИИН (физлицо) или БИН (юрлицо).
         ИИН проверяется алгоритмом (контрольная сумма mod 11),
         из номера расшифровываются дата рождения и пол.
         Правило: 1 ИИН = 1 аккаунт (защита от дублей).
         ПОСЛЕ ЭТОГО → Шаг 4.
  Шаг 4  ИИ-чат «Опишите недвижимость»
         Клиент пишет текстом (например: «2-комнатная квартира
         55 м2, 5 этаж из 9, Алматы, Алатауский район, 1985 года»)
         или прикладывает фото.
         ПОСЛЕ ЭТОГО → Шаг 5.
  Шаг 5  Оценка от ИИ [ESTIMATE]
         ИИ возвращает: диапазон рыночной стоимости (±10-15%),
         анализ района, рекомендации.
         ПОСЛЕ ЭТОГО → Шаг 6.
  Шаг 6  Кнопка «Оплатить официальный отчёт»
         Цена: 15 000 тенге. Заявка создаётся автоматически
         (source = 'ai').
         ПОСЛЕ ЭТОГО → Шаг 7.
  Шаг 7  Выбор способа оплаты
         Kaspi-перевод / карта / вручную менеджеру.
         РАЗВИЛКА: если оплата не прошла/не подтверждена →
         возврат к Шагу 7 (выбор другого способа) или отмена.
         ПОСЛЕ ЭТОГО → Шаг 8.
  Шаг 8  Ожидание подтверждения оплаты
         Админ проверяет перевод → статус заявки paid.
         РАЗВИЛКА: если админ отклонил → статус rejected, путь
         завершён (клиент может обратиться в поддержку).
         ПОСЛЕ ЭТОГО → Шаг 9.
  Шаг 9  Заявка у оценщика
         Оценщик берёт заявку → статус in_progress.
         ПОСЛЕ ЭТОГО → Шаг 10.
  Шаг 10 Предпросмотр PDF
         Клиент видит ПРЕДВАРИТЕЛЬНЫЙ PDF с водяным знаком
         (можно ознакомиться, официально использовать нельзя).
         ПОСЛЕ ЭТОГО → Шаг 11.
  Шаг 11 Подписание ЭЦП (делает оценщик)
         Оценщик готовит официальный PDF-отчёт (шаблон GaMa
         Group) и подписывает электронной цифровой подписью
         (NCALayer или .cms) → статус signed.
         ПОСЛЕ ЭТОГО → Шаг 12.
  Шаг 12 Заявка завершена
         Статус completed.
         ПОСЛЕ ЭТОГО → Шаг 13.
  Шаг 13 Скачивание официального отчёта
         Клиент получает финальный PDF без водяного знака.
         Ссылка защищённая, действует 1 час. Документ годится
         для банка, нотариуса, суда, сделки. → КОНЕЦ ПУТИ.

================================================================
ЗАДАЧА 2. РОАДМАП ОЦЕНЩИКА (пошагово)
================================================================
Построй отдельный flowchart LR из 8 шагов:

  Шаг 1  Вход в кабинет оценщика → Шаг 2
  Шаг 2  Лента заявок: «доступные» (новые, ещё не взятые)
         и «мои» (в работе) → Шаг 3
  Шаг 3  Взять заявку → статус in_progress → Шаг 4
  Шаг 4  Работа: документы клиента, данные объекта → Шаг 5
  Шаг 5  ИИ-помощь: расчёты и текст отчёта → Шаг 6
  Шаг 6  Генерация PDF-отчёта по шаблону GaMa Group → Шаг 7
  Шаг 7  ЭЦП-подписание: NCALayer (свой ключ, ws://127.0.0.1:13579)
         ИЛИ загрузка готового .cms (ezSigner). Подпись
         проверяется, данные подписанта сохраняются → Шаг 8
  Шаг 8  Заявка completed → клиент видит отчёт. → КОНЕЦ ПУТИ.

================================================================
ЗАДАЧА 3. РОАДМАП АДМИНА (пошагово)
================================================================
Построй flowchart LR из 6 шагов:

  Шаг 1  Вход в админку → Шаг 2
  Шаг 2  Обзор: заявки, пользователи, документы, платежи → Шаг 3
  Шаг 3  Проверка оплаты (Kaspi-перевод) → подтвердить →
         статус paid → Шаг 4
  Шаг 4  Проверка идентификации клиентов (ФИО из ИИН, дата
         рождения, пол) → Шаг 5
  Шаг 5  Блокировка нарушителей (is_blocked) → Шаг 6
  Шаг 6  Управление B2B-ключами (API v1). → КОНЕЦ ПУТИ.

================================================================
ЗАДАЧА 4. СВОДНЫЙ ГРАФ СТАТУСОВ ЗАЯВКИ
================================================================
Построй Mermaid stateDiagram-v2:
  new → pending_payment (клиент нажал «Оплатить»)
  pending_payment → paid (админ подтвердил)
  paid → in_progress (оценщик взял заявку)
  in_progress → signed (оценщик подписал ЭЦП)
  signed → completed (отчёт готов)
  new → rejected (админ отклонил)
  pending_payment → new (клиент отменил оплату)
  in_progress → completed (отчёт готов без ЭЦП)

ПРАВИЛА
================================================================
- Каждый узел: номер + краткое название (2-5 слов).
- Между узлами — ТОЛЬКО стрелки «→»: последовательность должна
  читаться как «после этого идёт это».
- Развилки (оплата подтверждена? заявка отклонена?) — ромбами
  { ... } в flowchart.
- Mermaid-код внутри блоков ```mermaid ... ```, тип flowchart LR.
- Глубина не больше 4 уровней. Ничего не выдумывать.
- Язык — русский.

ФОРМАТ ВЫВОДА (все три варианта обязательны)
================================================================
Вариант A — Mermaid-код (главный):
  1) flowchart LR полного пути клиента (13 шагов с развилками);
  2) flowchart LR пути оценщика;
  3) flowchart LR пути админа;
  4) stateDiagram-v2 статусов заявки.

Вариант B — текстовый контур со стрелками:
  Каждый путь одной цепочкой, по одному шагу на строку:
    1. Регистрация → 2. Онбординг → 3. Профиль и идентификация
    → 4. ИИ-чат → 5. Оценка от ИИ → ...
  Под цепочкой — краткое пояснение каждого перехода: «после
  регистрации пользователь попадает в онбординг, где ...».

Вариант C — mind map для общего обзора (Mermaid mindmap):
  Корень: ESEP — онлайн-оценка недвижимости.
  Ветки (5): Клиент / Оценщик / Админ / Статусы заявки / Технологии.
  Подветки — шаги с номерами (1. Регистрация, 2. Онбординг ...).

В конце — краткая сводка (3-5 строк): сколько шагов в каждом
пути, где развилки, какие ветки самые подробные.
