1.1. ESEP ЗА 30 СЕКУНД
----------------------------------------------------------------
ESEP — онлайн-сервис оценки недвижимости в Казахстане.

Клиент описывает квартиру/дом в ИИ-чате (текстом или фото) →
ИИ сразу даёт рыночную стоимость (±10-15%) → клиент оплачивает
официальный отчёт (15 000 тенге) → профессиональный оценщик
проверяет данные, готовит PDF-отчёт по стандарту оценочной
компании и подписывает его электронной цифровой подписью (ЭЦП) →
клиент скачивает юридически значимый документ для банка,
нотариуса, суда или сделки.

Роли:
  • Клиент    — заказывает оценку, платит, скачивает отчёт.
  • Оценщик   — берёт заявки, готовит и подписывает отчёты ЭЦП.
  • Админ     — подтверждает оплаты, управляет пользователями.

1.2. РОАДМАП ПОЛЬЗОВАТЕЛЯ
----------------------------------------------------------------
--- 1.2.1. КЛИЕНТ (обычный человек) -----------------------------
 Шаг 1. Регистрация
        Email/телефон + пароль, вход по коду (Supabase Auth).
 Шаг 2. Онбординг
        Интерактивная экскурсия по приложению (5 шагов):
        как заказать оценку, что нужно, сколько стоит.
 Шаг 3. Профиль и идентификация
        ФИО + ИИН (физлицо) или БИН (юрлицо). ИИН проверяется
        алгоритмом (контрольная сумма mod 11), из номера
        расшифровываются дата рождения и пол.
        Правило: 1 ИИН = 1 аккаунт (защита от дублей).
 Шаг 4. ИИ-чат «Опишите недвижимость»
        Текст: «2-комнатная квартира 55 м2, 5 этаж из 9, Алматы,
        Алатауский район, 1985 года» — или фото.
        ИИ возвращает: диапазон стоимости, анализ района,
        рекомендации. Кнопка «Оплатить официальный отчёт».
 Шаг 5. Оплата (15 000 тенге)
        Способы: Kaspi-перевод / банковский перевод по реквизитам
        ТОО «GaMa Group» (БИН 160840018855, ИИК KZ646017131000019202).
        После оплаты заявка уходит оценщику.
 Шаг 6. Ожидание и предпросмотр
        Прогресс: «Оплачено → Оценщик работает».
        Доступен ПРЕДВАРИТЕЛЬНЫЙ PDF с водяным знаком
        (для ознакомления, официально использовать нельзя).
 Шаг 7. Подписание ЭЦП (делает оценщик)
        Оценщик подписывает отчёт своей ЭЦП (NCALayer) —
        документ становится юридически значимым.
 Шаг 8. Скачивание официального отчёта
        Финальный PDF без водяного знака — для банка, нотариуса,
        сделки. Ссылка защищённая, действует 1 час.

--- 1.2.2. ОЦЕНЩИК (профессионал) -------------------------------
 Шаг 1. Вход в кабинет оценщика.
 Шаг 2. Лента заявок: «доступные» (новые, не взятые) и «мои».
 Шаг 3. Взял заявку → статус in_progress.
 Шаг 4. Работа: видит документы клиента и данные объекта,
        ИИ помогает с расчётами и текстом отчёта.
 Шаг 5. Генерация PDF-отчёта по шаблону оценочной компании.
 Шаг 6. ЭЦП-подписание: NCALayer (своим ключом) или загрузка
        готового .cms-файла (ezSigner). Подпись проверяется,
        данные подписанта сохраняются.
 Шаг 7. Заявка завершена (completed) — клиент видит отчёт.

--- 1.2.3. АДМИН (менеджер) --------------------------------------
 • Все заявки, пользователи, документы, платежи в одном окне.
 • Подтверждает оплату вручную (проверил Kaspi-перевод → paid).
 • Видит идентификационные данные клиентов (ФИО, дату рождения,
   пол — из ИИН) для проверки.
 • Блокирует нарушителей.
 • Управляет B2B-ключами (API v1 для партнёров).

----------------------------------------------------------------
2.1. АРХИТЕКТУРА
----------------------------------------------------------------
 Flutter (Web / iOS / Android)  ──►  Cloudflare Pages (esep.pages.dev)
        │                        │
        │ HTTPS                  │ functions/api/chat.js (edge)
        ▼                        ▼
   Supabase              Gemini API (основной ИИ)
   ├─ Auth (JWT)         OpenRouter (фолбэк)
   ├─ Postgres + RLS     (бесплатные модели Gemma)
   ├─ Storage (приватные бакеты: reports/, user-docs/)
   └─ Realtime
        ▲
        └─ GitHub Actions (deploy.yml): push в master → деплой

 Ключевое решение: весь «умный» код — в edge-функции Cloudflare,
 секреты (ключи ИИ) никогда не попадают в клиент и в репозиторий.

2.3. БАЗА ДАННЫХ (Postgres)
----------------------------------------------------------------
 Таблица          Назначение
 ---------------------------------------------------------------
 profiles         профили: роль, ИИН/БИН, ФИО, блокировка
 properties       объекты недвижимости (тип, адрес, площадь...)
 applications     заявки: статус (new → pending_payment →
                  in_progress → completed / paid / rejected),
                  оценщик, данные подписи (signer_name/iin)
 documents        документы пользователя (для ИИ и оценщика)
 payments         платежи: сумма, метод, статус, кто подтвердил
 reports          отчёты: статус (draft/preview/paid/signed),
                  путь к PDF в приватном бакете, подписант
 ai_conversations история чатов с ИИ
 api_keys         B2B-ключи (хранятся только хэши)
 activity_logs    аудит действий
 market_data      рыночные данные (задел под аналитику)
 appraisals       резервная таблица оценок

 Индексы и ограничения: 1 ИИН = 1 аккаунт (unique), статусы
 заявок (check), FK на auth.users, триггеры updated_at.

----------------------------------------------------------------
2.4. ИИ-ИНТЕГРАЦИЯ (GEMINI + OPENROUTER)
----------------------------------------------------------------
 • Все запросы идут через edge-функцию /api/chat; ключи живут
   только в секретах Cloudflare (в коде клиента их нет).
 • Схема: Gemini (текст — flash-lite; фото — 2.5-flash с поиском
   по интернету) → при ошибке/лимите фолбэк на OpenRouter
   (бесплатные Gemma-модели).
 • Функция проверяет JWT пользователя (Authorization: Bearer):
   посторонние не могут жечь чужую квоту; заблокированные
   пользователи получают 403.
 • Умения ИИ:
     - оценка стоимости по описанию/фото [ESTIMATE],
     - анализ района и рекомендации,
     - помощь оценщику в составлении отчёта,
     - чтение загруженных документов клиента.

----------------------------------------------------------------
2.5. БЕЗОПАСНОСТЬ (проверено аудитом 11.08.2026)
----------------------------------------------------------------
 • ЭЦП-подписание — ТОЛЬКО оценщик/админ (UI + RLS: клиент не
   может проставить поля подписи).
 • PDF-отчёты — в приватном бакете; скачивание только владельцем
   заявки / оценщиком / админом по временной signed-ссылке.
 • Пользователь не может сам сменить себе роль или снять
   блокировку.
 • Клиент не может пометить отчёт «оплачен/подписан» сам.
 • Платёж можно создать только по своей заявке.
 • /api/chat защищён JWT.
 • 1 ИИН = 1 аккаунт (уникальный индекс).
 • Секреты — только в env (Cloudflare/GitHub), не в репозитории.

----------------------------------------------------------------
2.6. ДЕПЛОЙ И ИНФРАСТРУКТУРА
----------------------------------------------------------------
 Процесс: push в master → GitHub Actions (build web --release)
 → Cloudflare Pages (проект 'esep') → esep.pages.dev.
 SPA-redirects настроены; секреты синхронизируются через
 wrangler pages secret.

 Окружение (env):
   GEMINI_API_KEY      — основной ИИ-ключ
   OPENROUTER_API_KEY  — фолбэк
   GEMINI_TEXT_MODEL   — опционально
   GEMINI_VISION_MODEL — опционально
   SUPABASE_URL        — авторизация /api/chat
   SUPABASE_ANON_KEY   — авторизация /api/chat
   CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID — CI
