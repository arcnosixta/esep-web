1. ЧТО ТАКОЕ ESEP — ПРОСТЫМИ СЛОВАМИ
================================================================
ESEP — это онлайн-сервис оценки недвижимости в Казахстане.

Вместо того чтобы звонить оценщику, ждать, ездить по инстанциям,
пользователь просто описывает свою квартиру/дом в чате (текстом
или фото) — и искусственный интеллект сразу называет примерную
рыночную стоимость (±10-15%). Дальше клиент оплачивает официальный
отчёт (15 000 тенге), профессиональный оценщик проверяет данные,
готовит полноценный PDF-отчёт по стандарту оценочной компании
и подписывает его электронной цифровой подписью (ЭЦП — это как
личная подпись, только электронная и юридически значимая в РК).

Клиент в личном кабинете видит весь путь своей заявки: от «новая»
до «оплачена → оценщик работает → отчёт подписан → можно скачать».
Официальный PDF с печатью и ЭЦП подходит для банков, нотариусов,
суда и сделок.

Роли в системе:
  • Клиент — заказывает оценку, платит, скачивает отчёт.
  • Оценщик — берёт заявки, готовит и подписывает отчёты ЭЦП.
  • Админ — подтверждает оплаты, управляет пользователями и документами.

2. РОАДМАП ПОЛЬЗОВАТЕЛЯ
================================================================
----------------------------------------------------------------
2.1. КЛИЕНТ (обычный человек)
----------------------------------------------------------------
 Шаг 1. Регистрация
        Email/телефон + пароль. Вход по коду (Supabase Auth).
 Шаг 2. Онбординг
        Интерактивная экскурсия по приложению (5 шагов):
        как заказать оценку, что нужно, сколько стоит.
 Шаг 3. Профиль и идентификация
        Указывает ФИО и ИИН (физлицо) или БИН (юрлицо).
        ИИН проверяется алгоритмом (контрольная сумма mod 11),
        из номера расшифровываются дата рождения и пол.
        Правило: 1 ИИН = 1 аккаунт (защита от дублей).
 Шаг 4. ИИ-чат «Опишите недвижимость»
        Пишет: «2-комнатная квартира 55 м2, 5 этаж из 9,
        Алматы, Алатауский район, 1985 года» — или прикладывает фото.
        ИИ (Gemini) возвращает оценку: диапазон стоимости,
        анализ района, рекомендации. [ESTIMATE]
 Шаг 5. Оплата официального отчёта
        Кнопка «Оплатить официальный отчёт» — 15 000 тенге.
        Способы: Kaspi перевод / карта / вручную менеджеру.
        После оплаты заявка уходит оценщику.
 Шаг 6. Ожидание и предпросмотр
        Клиент видит прогресс: «оплачено → оценщик работает».
        Доступен ПРЕДВАРИТЕЛЬНЫЙ PDF с водяным знаком
        (ознакомиться, но не использовать официально).
 Шаг 7. Подписание ЭЦП (делает оценщик)
        Оценщик подписывает отчёт своей электронной подписью
        (NCALayer) — отчёт становится юридически значимым.
 Шаг 8. Скачивание официального отчёта
        Клиент получает доступ к финальному PDF (без водяного знака)
        — для банка, нотариуса, сделки. Ссылка защищённая, действует
        1 час.

----------------------------------------------------------------
2.2. ОЦЕНЩИК (профессионал)
----------------------------------------------------------------
 Шаг 1. Вход в кабинет оценщика.
 Шаг 2. Лента заявок: «доступные» (новые, ещё никем не взятые)
        и «мои» (в работе).
 Шаг 3. Взял заявку → статус in_progress.
 Шаг 4. Работа: видит документы клиента, данные объекта,
        может попросить ИИ помочь с расчётами/текстом.
 Шаг 5. Генерация отчёта: PDF по шаблону оценочной компании,
        с данными клиента, объекта, рыночным анализом.
 Шаг 6. ЭЦП-подписание: через NCALayer (своим ключом)
        или загрузка готового .cms-файла (ezSigner).
        Подпись проверяется, данные подписанта сохраняются.
 Шаг 7. Заявка завершена (completed) — клиент видит отчёт.

----------------------------------------------------------------
2.3. АДМИН (менеджер)
----------------------------------------------------------------
 • Все заявки, пользователи, документы, платежи в одном окне.
 • Подтверждает оплату вручную (Kaspi-перевод проверен → paid).
 • Видит идентификационные данные клиентов (ФИО из ИИН,
   дату рождения, пол) — для проверки.
 • Блокирует нарушителей (is_blocked).
 • Управляет B2B-ключами (API v1 для партнёров).

3. ТЕХНИЧЕСКИЕ ХАРАКТЕРИСТИКИ
================================================================
----------------------------------------------------------------
3.1. Архитектура
----------------------------------------------------------------
 Flutter Web (PWA)  ──►  Cloudflare Pages (esep.pages.dev)
        │                        │
        │ HTTPS                  │ functions/api/chat.js (edge)
        ▼                        ▼
   Supabase              Gemini API (основной)
   ├─ Auth (JWT)         OpenRouter (фолбэк)
   ├─ Postgres + RLS     (бесплатные модели Gemma)
   ├─ Storage (приватные бакеты: reports/, user-docs/)
   └─ Realtime
        ▲
        └─ GitHub Actions (deploy.yml): push в master → сборка → деплой

----------------------------------------------------------------
3.2. Стек
----------------------------------------------------------------
 Фронтенд:      Flutter / Dart 3.12, web + мобильные платформы
                (android/ios/linux/macos/windows — scaffolding готов)
 UI-библиотеки: google_fonts, phosphor_flutter (иконки),
                flutter_animate (анимации), confetti (праздник оплаты)
 Бэкенд:        Supabase (auth, Postgres, RLS, storage)
 Edge:          Cloudflare Pages Function functions/api/chat.js
 ИИ:            Gemini API (gemini-flash-lite-latest — текст,
                gemini-2.5-flash — фото + поиск по вебу),
                фолбэк на OpenRouter (gemma-4-31b-it:free и др.)
 PDF:           пакеты pdf + printing (генерация и печать/шаринг),
                шаблон отчёта GaMa Group
 ЭЦП:           NCALayer (ws://127.0.0.1:13579, CMSSignUtil) —
                десктоп; загрузка .cms (ezSigner); парсер и
                верификатор CMS-подписей встроены
 Платежи:       ручное подтверждение (manual), Kaspi/карта;
                задел под провайдера (PayBox/Kaspi API)
 Безопасность:  JWT, RLS-политики на все таблицы, приватные
                бакеты storage + signed URL, ролевой доступ

----------------------------------------------------------------
3.3. База данных (Postgres, таблицы)
----------------------------------------------------------------
 profiles         — профили: роль (client/appraiser/admin),
                    ИИН/БИН, ФИО, блокировка
 properties       — объекты недвижимости (тип, адрес, площадь...)
 applications     — заявки: статус (new → pending_payment →
                    in_progress → completed / paid / rejected),
                    оценщик, подпись (signer_name/iin/signature)
 documents        — документы пользователя (для ИИ и оценщика)
 payments         — платежи: сумма, метод, статус, кто подтвердил
 reports          — отчёты: статус (draft/preview/paid/signed),
                    путь к PDF в приватном бакете, подписант
 ai_conversations — история чатов с ИИ
 api_keys         — B2B-ключи (хранятся только хэши)
 activity_logs    — аудит действий
 market_data      — рыночные данные (задел под аналитику)
 appraisals       — резервная таблица оценок

----------------------------------------------------------------
3.4. ИИ-интеграция (Gemini + OpenRouter)
----------------------------------------------------------------
 • Все запросы идут через edge-функцию /api/chat (секреты ключей
   хранятся ТОЛЬКО на сервере Cloudflare, в клиенте ключей нет).
 • Схема: сначала Gemini (текст — flash-lite, фото — 2.5-flash
   с поиском по интернету), при ошибке/лимите — прозрачный
   фолбэк на OpenRouter (бесплатные модели Gemma).
 • Функция проверяет JWT пользователя (Authorization: Bearer) —
   посторонние не могут жечь чужую квоту; заблокированные
   пользователи получают 403.
 • ИИ умеет: оценка стоимости по описанию/фото [ESTIMATE],
   помощь в составлении отчёта, чтение загруженных документов.

----------------------------------------------------------------
3.5. Безопасность (что закрыто аудитом 11.08.2026)
----------------------------------------------------------------
 • ЭЦП-подписание доступно ТОЛЬКО оценщику/админу (UI + RLS:
   клиент не может проставить поля подписи).
 • PDF-отчёты в приватном бакете: скачивание только владельцем
   заявки/оценщиком/админом, по временной signed-ссылке.
 • Пользователь не может сам сменить себе роль/снять блокировку.
 • Клиент не может пометить отчёт «оплачен/подписан» сам.
 • Платёж можно создать только по СВОЕЙ заявке.
 • /api/chat защищён JWT.
 • 1 ИИН = 1 аккаунт (уникальный индекс).

4.2. Психологические принципы для доработки
----------------------------------------------------------------
 1. ДОВЕРИЕ — главная валюта оценки недвижимости.
    • Значки «ЭЦП», «Защита данных», «1 ИИН = 1 аккаунт»
      на экране оплаты и в шапке.
    • Показать ФИО и сертификат оценщика перед подписанием.
    • Футер: «Работаем по закону РК об оценочной деятельности».
 2. СНИЖЕНИЕ ТРЕВОЖНОСТИ НА ПУТИ ОПЛАТЫ.
    • До оплаты — ясная цена (15 000 ₸) и что в неё входит.
    • После оплаты — мгновенная обратная связь:
      confetti + «Оплачено! Оценщик уже получил вашу заявку».
    • Показ «что будет дальше» (3 пункта) — убирает неопределённость.
 3. ОЩУЩЕНИЕ ПРОГРЕССА.
    • Сделать степпер эмоциональнее: иконки-иллюстрации на каждом
      этапе, анимированный «путь» заявки (как трекер доставки).
    • Статусы писать человеческим языком:
      «Оплачено», «Оценщик работает», «Отчёт подписан ЭЦП»,
      «Готово — можно скачивать».
 4. МОМЕНТЫ РАДОСТИ (AHA-моменты).
    • Confetti уже при оплате — добавить при подписании отчёта
      и при скачивании первого официального PDF.
    • «Первый отчёт получен» — поздравление с бейджем.
 5. КОГНИТИВНАЯ ЛЁГКОСТЬ.
    • 1 экран = 1 главное действие. На экране оплаты — только
      «Оплатить», без лишних ссылок.
    • Крупные цели для пальца (не меньше 48px).
    • Шрифт: единая типографика через google_fonts (уже подключён).
 6. СОЦИАЛЬНОЕ ДОКАЗАТЕЛЬСТВО.
    • Счётчик: «Проведено 1 240 оценок», «Среднее время отчёта —
      2 дня».
    • Отзывы клиентов на главном экране (блок-задел).
 7. ДОСТУПНОСТЬ.
    • Контраст текста не ниже WCAG AA.
    • Тёмная/светлая тема — переключатель (есть задел в настройках).
    • Все состояния: загрузка (skeleton), ошибка, пусто — с
      понятным текстом и кнопкой действия.
 8. МОБИЛЬНОСТЬ.
    • Сейчас веб-PWA; адаптировать все экраны под узкие экраны
      (375px), проверить жесты и размеры кнопок.

5. ЧТО КУПИТЬ И ИНТЕГРИРОВАТЬ
================================================================
 Приоритет: [P0] критично, [P1] скоро, [P2] потом.

 [P0] 1. Платёжный провайдер (Kaspi Pay / PayBox)
        Сейчас оплата подтверждается вручную админом. Нужен
        автоприём: Kaspi Pay (комиссия ~1,5-2% с платежа) или
        PayBox (РК). Интеграция: вебхук → статус paid автоматически.
        Стоимость: комиссия ~225-300 ₸ с заказа 15 000 ₸.

 [P0] 2. Домен esep.kz (сейчас esep.pages.dev)
        Свой домен = доверие + SEO. Регистрация .kz ~5-8 тыс ₸/год
        (через регистратора: KazNIC-партнёры, reg.kz и т.п.).

 [P1] 3. Подписка Supabase Pro ($25/мес ≈ 12 500 ₸/мес)
        Free-тир ограничен (2 проекта, пауза при простое).
        Pro нужен, когда появятся первые платящие клиенты.

 [P1] 4. SIGEX (электронная подпись для документов)
        Альтернатива/дополнение к QR-подписи eGov mobile.
        Бесплатно до 40 документов/мес; Lite — 10 000 ₸/мес.
        Интеграция: sigex-qr-signing-client (клиент уже заложен).

 [P1] 5. Smart Bridge — eGov интеграции (официальные данные)
        • QR-подпись eGov mobile: услуга NITEC-S-5096 (вне ЕТС).
        • Кадастр (ЕГКН): ORGB7-S-6809 — характеристики объекта
          по адресу/кадастровому номеру.
        • ГБД ФЛ (настоящее ФИО по ИИН): MINJ-S-0086 — в ЕТС
          госорганов, этап 2.
        Тарифы: по прайсу услуг (ориентир от 500-1 000 ₸/запрос).

 [P1] 6. Gemini API — платный тир (если вырастем из бесплатного)
        Free: flash-lite — 60 запросов/мин. При росте — pay-as-you-go,
        ориентир $5-10/мес (≈2 500-5 000 ₸).

 [P1] 7. OpenRouter — пополнение (если free-моделей не хватит)
        Сейчас используем бесплатные Gemma. Платная квота — $5/мес
        (≈2 500 ₸) как страховка при лимитах Gemini.

 [P2] 8. SMS-провайдер (верификация телефона)
        Напр. SMS-центр РК, ~5-10 ₸/SMS. Нужен для усиления
        регистрации и уведомлений о статусе.

 [P2] 9. Дизайнер (UX/UI-аудит по разделу 4)
        Разовая работа: ориентир 150-300 тыс ₸ по рынку РК.

 [P2] 10. Юридическое оформление
        ИП/ТОО, публичная оферта, политика ПДн (Закон РК
        «О персональных данных»), договор с оценщиками.
        Ориентир: 50-150 тыс ₸ разово.

 [P2] 11. Мониторинг и аналитика
        Sentry (бесплатный тир 5k событий/мес), Яндекс.Метрика
        (бесплатно), Google Analytics 4 (бесплатно).

   (~5 000 ₸/мес у аналогов).
